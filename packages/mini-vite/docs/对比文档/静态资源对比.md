# 静态资源对比

对比 mini-vite 与完整 Vite 的静态资源处理能力。

## 资源类型对比

### mini-vite 支持的资源类型

| 资源类型 | 支持情况 | 处理方式 |
|----------|----------|----------|
| CSS | ✅ | 注入到 HTML，支持 HMR |
| JavaScript | ✅ | esbuild 编译，支持 HMR |
| TypeScript | ✅ | esbuild 编译 |
| HTML | ✅（入口） | 注入脚本和 HMR 客户端 |
| CommonJS | ✅ | 转换为 ESM |

### mini-vite 未支持的资源类型

| 资源类型 | Vite 支持 | mini-vite |
|----------|-----------|-----------|
| 图片（png/jpg/gif/svg/webp） | ✅ | ❌ |
| 字体（woff/woff2/ttf/eot） | ✅ | ❌ |
| JSON | ✅ | ❌ |
| Web Worker | ✅ | ❌ |
| WebAssembly | ✅ | ❌ |
| SVG | ✅ | ❌ |
| Media（mp4/webm/mp3） | ✅ | ❌ |

## CSS 处理对比

### mini-vite CSS 处理

```typescript
// plugins/css.ts
// 简化处理流程
export function cssPlugin(): Plugin {
    return {
        name: 'mini-vite:css',
        load(id) {
            if (id.endsWith('.css')) {
                // 读取 CSS 文件
                return readCss(id)
            }
        },
        transform(code, id) {
            if (id.endsWith('.css')) {
                // 转换为 JS 模块
                // 创建 style 标签注入
                return {
                    code: `
                        const style = document.createElement('style')
                        style.textContent = ${JSON.stringify(code)}
                        document.head.appendChild(style)
                    `
                }
            }
        }
    }
}
```

### Vite CSS 处理

```typescript
// vite 完整 CSS 处理能力
// plugins/css.ts

// 1. 支持 CSS Modules
import styles from './App.module.css'
// 输出: { container: '_container_123', ... }

// 2. 支持 PostCSS
// 自动应用 postcss.config.js 配置

// 3. 支持 CSS 预处理器
import './App.scss'    // Sass
import './App.less'    // Less
import './App.styl'    // Stylus

// 4. 支持 @import 解析
// 处理 CSS 文件中的 @import

// 5. 支持 CSS HMR
// CSS 变更时仅更新样式，不刷新页面

// 6. 生产构建 CSS 分离
// CSS 提取到独立文件
```

### CSS 处理对比表

| 方面 | mini-vite | Vite |
|------|-----------|------|
| CSS 注入 | JS 模块注入 style | 支持 JS 注入 + 生产分离 |
| CSS Modules | ❌ | ✅ |
| PostCSS | ❌ | ✅ |
| Sass/Less/Stylus | ❌ | ✅（需安装预处理器） |
| @import 处理 | ❌ | ✅ |
| CSS HMR | ✅（简化） | ✅（完整） |
| CSS 代码分割 | ❌ | ✅ |

## 图片资源对比

### mini-vite

mini-vite 不处理图片资源，需要用户自行处理。

### Vite 图片处理

```typescript
// vite 处理图片
import img from './logo.png'

// 开发模式
img  // => '/src/logo.png'

// 生产模式（带 hash）
img  // => '/assets/logo.abc123.png'

// 配置
export default {
    assetsInclude: ['**/*.png'], // 资源类型配置
    build: {
        assetsInlineLimit: 4096  // 小于 4KB 内联为 base64
    }
}

// SVG 特殊处理
import svg from './icon.svg'
svg  // => SVG 字符串，可作为组件使用

// 或作为 URL
import svgUrl from './icon.svg?url'
svgUrl  // => '/assets/icon.abc123.svg'
```

## JSON 处理对比

### mini-vite

不支持 JSON 文件导入。

### Vite JSON 处理

```typescript
// vite 处理 JSON
import data from './data.json'
data  // => { key: 'value', ... }

// 支持具名导出
import { key } from './data.json'
key  // => 'value'

// 配置
export default {
    json: {
        stringify: true  // 导出为 JSON 字符串
    }
}
```

## Worker 处理对比

### mini-vite

不支持 Web Worker。

### Vite Worker 处理

```typescript
// vite 处理 Worker
import MyWorker from './worker?worker'
const worker = new MyWorker()

// 内联 Worker（小于 inlineThreshold）
import InlineWorker from './worker?worker&inline'

// 配置
export default {
    worker: {
        format: 'es',         // Worker 格式
        plugins: () => [],    // Worker 专用插件
    }
}
```

## WASM 处理对比

### mini-vite

不支持 WebAssembly。

### Vite WASM 处理

```typescript
// vite 处理 WASM
import wasm from './module.wasm'
const instance = await WebAssembly.instantiate(wasm)

// 或
import init from './module.wasm?init'
init().then(instance => { ... })
```

## 资源 URL 处理对比

### mini-vite

不处理资源 URL，裸模块导入会被 importAnalysis 重写为预构建路径。

### Vite URL 处理

```typescript
// vite URL 处理方式

// 1. 相对路径 URL
import imgUrl from './img.png'
imgUrl  // => 带 hash 的 URL

// 2. 绝对路径 URL
const imgUrl = '/img.png'  // 直接使用

// 3. URL 查询参数
import foo from './foo.js?url'     // 返回 URL
import bar from './bar.js?raw'     // 返回原始字符串
import baz from './baz.js?inline'  // 内联

// 4. public 目录
// public/ 目录下的文件直接复制，通过 /xxx 访问
```

## public 目录对比

### mini-vite

不支持 public 目录。

### Vite public 目录

```
project/
├── public/
│   ├── favicon.ico
│   └── robots.txt
├── src/
└── index.html

// public 目录下的文件：
// 1. 开发时通过 /xxx 直接访问
// 2. 生产构建时直接复制到输出目录
// 3. 无需 import，直接在 HTML 中引用
```

## 学习要点

1. **CSS 处理**是静态资源的核心功能之一
2. **CSS Modules 和预处理器**是实际项目必需
3. **资源 URL 处理**决定了资源的引入方式
4. **Worker 和 WASM**支持更复杂的应用场景
5. **public 目录**提供了静态资源直接访问的能力

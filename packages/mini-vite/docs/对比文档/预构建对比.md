# 预构建对比

对比 mini-vite 与完整 Vite 的依赖预构建机制。

## 预构建目的

预构建解决的核心问题在两个版本中一致：

1. **CommonJS/UMD 模块兼容** - 转换为 ESM 格式
2. **减少模块请求** - 将多入口依赖打包成单文件
3. **提升冷启动速度** - 使用 esbuild（比 Rollup 快 10-100 倍）

## 预构建流程对比

### mini-vite 预构建流程

```
启动开发服务器
    ↓
扫描依赖（deps.ts）
    │
    │  使用 esbuild 打包入口文件
    │  收集裸模块导入
    │
    ↓
预构建依赖（index.ts）
    │
    │  单 bundle 打包所有依赖
    │  输出到 .vite/deps/
    │
    ↓
写入缓存信息（_metadata.json）
    ↓
重写导入路径
```

### Vite 鐢预构建流程

```
启动开发服务器
    ↓
扫描依赖（scan.ts）
    │
    │  使用 esbuild 打包入口文件
    │  支持多入口（index.html + 多页面）
    │  收集裸模块导入
    │  处理动态导入
    │
    ↓
预构建依赖（index.ts）
    │
    │  多 bundle 打包（按入口分组）
    │  处理 linked 依赖（monorepo）
    │  输出到 node_modules/.vite/deps/
    │
    ↓
写入缓存信息（_metadata.json）
    │
    │  记录依赖 hash
    │  记录浏览器 hash
    │  记录优化结果
    │
    ↓
注册 HMR watcher
    ↓
重写导入路径
```

## 功能对比

### 依赖扫描

| 方面 | mini-vite | Vite |
|------|-----------|------|
| 扫描工具 | esbuild | esbuild |
| 入口文件 | 单入口（index.html） | 支持多入口 |
| 动态导入 | 不处理 | 处理动态导入依赖 |
| CSS 导入 | 不处理 | 处理 @import 依赖 |

### 依赖打包

| 方面 | mini-vite | Vite |
|------|-----------|------|
| 打包工具 | esbuild | esbuild |
| 输出格式 | 单 bundle | 多 bundle（按入口分组） |
| linked 依赖 | 不处理 | 支持 monorepo linked 依赖 |
| 强制排除 | 无 | `optimizeDeps.exclude` |
| 强制包含 | 无 | `optimizeDeps.include` |

### 缓存机制

| 方面 | mini-vite | Vite |
|------|-----------|------|
| 缓存位置 | `.vite/deps/` | `node_modules/.vite/deps/` |
| 缓存 hash | 依赖 hash | 依赖 hash + 浏览器 hash |
| 缓存失效 | 依赖变化时 | lockfile 变化 / 依赖变化 |
| 手动清除 | 无 | `optimizeDeps.force: true` |

## 源码对比

### mini-vite 预构建目录结构

```
mini-vite/src/node/optimizer/
├── deps.ts          # 依赖扫描
└── index.ts         # 预构建执行
```

### Vite 预构建目录结构

```
vite/src/node/optimizer/
├── index.ts         # 预构建主入口
├── scan.ts          # 依赖扫描
├── esbuildDepPlugin.ts  # esbuild 虚拟插件
├── optimizerBuild.ts    # 构建逻辑
└── deps.ts          # 依赖信息处理
```

## 缓存文件对比

### mini-vite _metadata.json

```json
{
    "hash": "依赖内容 hash",
    "dependencies": {
        "vue": {
            "file": "vue.js",
            "src": "vue"
        }
    }
}
```

### Vite _metadata.json

```json
{
    "hash": "优化结果 hash",
    "browserHash": "浏览器 hash",
    "optimized": {
        "vue": {
            "file": "vue.js",
            "src": "vue",
            "needsInterop": false
        }
    },
    "chunks": {
        "chunk-xxx": {
            "file": "chunk-xxx.js",
            "modules": ["module-a", "module-b"]
        }
    },
    "deps": {
        "vue": "vue"
    }
}
```

## 导入路径重写对比

### mini-vite 重写方式

```typescript
// plugins/importAnalysis.ts
// 简单替换：裸模块 -> 预构建产物路径
import vue from 'vue'
// 重写为
import vue from '/.vite/deps/vue.js'
```

### Vite 重写方式

```typescript
// plugins/importAnalysis.ts
// 复杂处理：
// 1. 检查是否需要预构建
// 2. 处理 linked 依赖
// 3. 处理动态导入
// 4. 注入 HMR 辅助代码
import vue from 'vue'
// 重写为
import vue from '/node_modules/.vite/deps/vue.js?v=hash'
```

## 配置对比

### mini-vite

mini-vite 不支持预构建配置。

### Vite optimizeDeps 配置

```typescript
// vite.config.ts
export default {
    optimizeDeps: {
        include: ['my-lib'],          // 强制预构建
        exclude: ['my-linked-lib'],   // 排除预构建
        esbuildOptions: { ... },      // esbuild 配置
        force: true,                  // 强制重建
        entries: ['index.html', 'main.js'], // 多入口
        noDiscovery: false,           // 禁用自动发现
    }
}
```

## 学习要点

1. **预构建的核心目的**是解决 ESM 兼容和减少请求
2. **esbuild 的速度**是预构建可行的基础
3. **缓存机制**避免每次启动都重新预构建
4. **多入口和 linked 依赖**是 Vite 完整版的重要优化

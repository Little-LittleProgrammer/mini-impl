# 热更新对比

对比 mini-vite 与完整 Vite 的热更新（HMR）机制。

## HMR 架构对比

### mini-vite HMR 架构

```
┌─────────────────┐     WebSocket      ┌─────────────────┐
│  HMR Server     │◄──────────────────►│  HMR Client     │
│  (server/hmr.ts)│                    │  (inject by     │
│                 │                    │   hmr plugin)   │
└─────────────────┘                    └─────────────────┘
        │                                       │
        │                                       │
        ▼                                       ▼
┌─────────────────┐                    ┌─────────────────┐
│  Module Graph   │                    │  Module Runtime │
│  (简化版)       │                    │  (import.meta)  │
└─────────────────┘                    └─────────────────┘
```

### Vite HMR 架构

```
┌─────────────────┐     WebSocket      ┌─────────────────┐
│  HMR Server     │◄──────────────────►│  HMR Client     │
│  (server/hmr.ts)│                    │  (client.ts)    │
│                 │                    │                 │
└─────────────────┘                    └─────────────────┘
        │                                       │
        │                                       │
        ▼                                       ▼
┌─────────────────┐                    ┌─────────────────┐
│  Module Graph   │                    │  Module Runtime │
│  (完整版)       │                    │  (import.meta)  │
│                 │                    │                 │
│  - modules      │                    │  - hot.accept() │
│  - importers    │                    │  - hot.dispose()│
│  - accepted     │                    │  - hot.data     │
│  - invalidated  │                    │                 │
└─────────────────┘                    └─────────────────┘
        │                                       │
        │                                       │
        ▼                                       ▼
┌─────────────────┐                    ┌─────────────────┐
│  File Watcher   │                    │  Update Handler │
│  (chokidar)     │                    │  (runtime.ts)   │
└─────────────────┘                    └─────────────────┘
```

## 功能对比

### WebSocket 通信

| 方面 | mini-vite | Vite |
|------|-----------|------|
| 协议 | WebSocket | WebSocket |
| 自定义协议 | 无 | 有（自定义消息格式） |
| 心跳检测 | 无 | 有 |
| 连接重试 | 简单 | 完善的重连机制 |

### 消息类型对比

**mini-vite 消息类型**

```typescript
// 服务端发送
{ type: 'update', updates: [...] }
{ type: 'error', err: {...} }

// 客户端发送
{ type: 'connected' }
```

**Vite 消息类型**

```typescript
// 服务端发送
{ type: 'update', updates: [...] }
{ type: 'full-reload', path: '...' }
{ type: 'prune', paths: [...] }
{ type: 'error', err: {...} }
{ type: 'custom', event: '...', data: {...} }

// 客户端发送
{ type: 'connected' }
{ type: 'import', url: '...' }
{ type: 'custom', event: '...', data: {...} }
```

### 模块图对比

| 方面 | mini-vite | Vite |
|------|-----------|------|
| ModuleNode 结构 | 简化 | 完整 |
| importers 记录 | 有 | 有 |
| importedModules | 有 | 有 |
| acceptedModules | 无 | 有 |
| isSelfAccepting | 无 | 有 |
| SSR 模块图 | 无 | 有独立模块图 |

**mini-vite ModuleNode**

```typescript
interface ModuleNode {
    url: string              // 模块路径
    importers: Set<string>   // 被谁导入
    importedModules: Set<string> // 导入了谁
    type: 'js' | 'css'       // 模块类型
}
```

**Vite ModuleNode**

```typescript
interface ModuleNode {
    url: string
    file: string | null
    type: 'js' | 'css' | 'html' | 'asset'
    importers: Set<ModuleNode>
    importedModules: Set<ModuleNode>
    acceptedModules: Set<ModuleNode>  // 接受的模块
    isSelfAccepting: boolean          // 是否自接受
    transformResult: TransformResult | null
    ssrTransformResult: TransformResult | null
    ssrModule: object | null
    lastHMRTimestamp: number
    lastInvalidationTimestamp: number
}
```

### 边界计算对比

| 方面 | mini-vite | Vite |
|------|-----------|------|
| 自动边界计算 | 有（向上追溯） | 有 |
| 手动边界控制 | 无 | `import.meta.hot.accept()` |
| 自接受模块 | 无 | 支持 |
| 模块 prune | 无 | 支持（清理失效模块） |

**mini-vite 边界计算**

```typescript
// 自动向上追溯找到更新边界
function findBoundary(node) {
    // 如果没有导入者，full reload
    // 否则收集所有导入者作为边界
}
```

**Vite 边界计算**

```typescript
// 支持手动边界
// 用户可以指定接受更新的方式
import.meta.hot.accept((newMod) => {
    // 自定义更新逻辑
})

// 或
import.meta.hot.accept(['./dep.js'], (mods) => {
    // 接受特定依赖的更新
})
```

### HMR API 对比

**mini-vite HMR API**

```typescript
// 仅注入基本 HMR 客户端
// 无具体 API 实现
import.meta.hot  // 存在但功能有限
```

**Vite HMR API**

```typescript
// 完整的 HMR API
import.meta.hot.accept(mods, cb)    // 接受更新
import.meta.hot.dispose(cb)         // 清理旧模块
import.meta.hot.decline()           // 拒绝更新
import.meta.hot.invalidate()        // 强制重新加载
import.meta.hot.data                // 跨更新数据
import.meta.hot.on(event, cb)       // 自定义事件
import.meta.hot.send(event, data)   // 发送事件
```

## 更新流程对比

### mini-vite 更新流程

```
文件变更
    ↓
文件 watcher 触发
    ↓
查找模块节点
    ↓
计算更新边界（自动）
    ↓
发送 update 消息
    ↓
客户端执行更新
    ↓
重新 import 模块
```

### Vite 更新流程

```
文件变更
    ↓
文件 watcher 触发
    ↓
触发 handleHotUpdate 钩子
    ↓
查找模块节点
    ↓
计算更新边界
    │
    │  优先使用 accept() 定义的手动边界
    │  否则向上自动追溯
    │
    ↓
发送 update/prune/full-reload
    ↓
客户端执行更新
    │
    │  执行 dispose() 清理
    │  执行 accept() 回调
    │  重新 import 模块
    │
    ↓
触发 custom HMR 事件
```

## 学习要点

1. **WebSocket + 模块图**是 HMR 的核心架构
2. **边界计算**决定了哪些模块需要更新
3. **Vite 的 `accept()` API**提供了更精细的更新控制
4. **`dispose()` 和 `data`**支持跨更新的状态保持

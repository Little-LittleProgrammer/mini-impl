# 架构总览

这一篇只回答架构问题：包怎么分、依赖怎么走、响应式、运行时、编译时在哪里接起来。

## 源码入口

- `packages/mini-vue/packages/vue/src/index.ts`
- `packages/mini-vue/packages/vue-compat/src/index.ts`
- `packages/mini-vue/packages/runtime-core/src/component.ts`
- `packages/mini-vue/packages/runtime-core/src/renderer.ts`
- `packages/mini-vue/packages/runtime-dom/src/index.ts`
- `packages/mini-vue/packages/compiler-core/src/compile.ts`

## 分层图

```text
用户入口 vue
  ├─ reactivity
  ├─ runtime-core
  ├─ runtime-dom
  ├─ vue-compat
  └─ shared

compiler-dom
  -> compiler-core

runtime-dom
  -> runtime-core
  -> reactivity
  -> shared
```

`vue` 入口做的是聚合导出，不是业务逻辑实现。真正的逻辑分别落在 `reactivity`、`runtime-core`、`runtime-dom`、`compiler-core`。

## 包职责

### `shared`

跨包工具层，包含：

- 类型判断：`isObject`、`isArray`、`isFunction`、`isString`
- 值比较：`hasChanged`
- 对象合并：`extend`
- props/class 辅助：`normalizeClass`
- VNode 类型位：`ShapeFlags`
- 文本显示：`toDisplayString`

它不依赖业务包，应该保持最底层。

### `reactivity`

响应式底层，核心文件：

- `reactive.ts`：创建 Proxy，并用 `WeakMap` 缓存原对象到 proxy 的映射。
- `baseHandlers.ts`：在 `get` 里 `track`，在 `set` 里 `trigger`。
- `effect.ts`：维护 `activeEffect`、依赖图、`ReactiveEffect`。
- `ref.ts`：通过 `.value` 的 getter/setter 收集和触发依赖。
- `computed.ts`：用内部 `ReactiveEffect` 和 `_dirty` 做缓存。
- `dep.ts`：把依赖集合定义为 `Set<ReactiveEffect>`。

响应式层不知道组件、VNode、DOM。它只负责“读时收集，写时触发”。

### `runtime-core`

平台无关运行时，核心文件：

- `vnode.ts`：创建和规范化 VNode。
- `renderer.ts`：`createRenderer`、`render`、`patch`、diff。
- `component.ts`：组件实例、`setup`、`data`、生命周期注册、运行时编译接缝。
- `scheduler.ts`：微任务队列。
- `apiCreateApp.ts`：应用实例的 `mount/unmount`。
- `apiWatch.ts`：`watch` 的当前实现。

它不直接调用 DOM API，而是接收 host 操作。

### `runtime-dom`

浏览器适配层，核心文件：

- `nodeOps.ts`：`insert`、`createElement`、`remove`、`createText` 等 DOM 操作。
- `patchProp.ts`：根据 `class/style/event/prop/attr` 分发属性更新。
- `modules/*`：具体处理 class、style、event、DOM prop、attribute。
- `index.ts`：合并 `nodeOps` 和 `patchProp`，创建浏览器 renderer。

### `compiler-core`

平台无关编译器，当前流程是：

```text
baseCompile(template)
  -> baseParse(template.trim())
  -> transform(ast, nodeTransforms)
  -> generate(ast)
```

它的目标不是完整模板编译，而是展示 Vue 编译器的三段式结构。

### `compiler-dom`

当前只是：

```ts
export function compile(template: string, options) {
  return baseCompile(template, options)
}
```

也就是说它还没有真正实现 DOM 平台特有的编译转换。

### `vue-compat`

这里的名字容易误导。它不是完整 Vue compat build，而是负责把编译器注册到运行时：

```text
compiler-dom.compile(template)
  -> 得到 code
  -> new Function(code)()
  -> 得到 render
  -> registerRuntimeCompiler(compileToFunction)
```

组件初始化时，如果组件没有 `render` 但有 `template`，`component.ts` 会调用这个注册进来的编译函数。

## 三条核心闭环

### 响应式更新闭环

```text
组件 render 执行
  -> 读取 reactive/ref
  -> track 收集当前组件 effect
  -> 修改 reactive/ref
  -> trigger 找到 dep
  -> scheduler 入队组件 update
  -> 微任务 flush
  -> effect.run 重新 render
  -> patch 更新 DOM
```

### VNode 渲染闭环

```text
h/createVNode
  -> VNode
  -> render(vnode, container)
  -> patch(oldVNode, newVNode)
  -> processElement/processComponent/processText/processFragment
  -> hostCreateElement/hostPatchProp/hostInsert
```

### 模板编译闭环

```text
template
  -> AST
  -> codegenNode
  -> render code string
  -> new Function(code)()
  -> render 函数
  -> 执行 render 得到 VNode
```

## 当前架构的真实定位

这份 mini-vue 的架构分层接近 Vue 3，但实现深度是教学级：

- 分层方法是对的。
- 核心链路能跑通。
- 很多高级能力只有类型名、注释或 TODO，没有完整实现。

所以阅读源码时，应优先看每个模块之间如何协作，再看具体 API 覆盖面。

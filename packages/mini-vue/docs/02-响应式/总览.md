# 响应式总览

响应式系统解决一个问题：状态被读取时记住谁依赖它，状态被写入时通知这些依赖重新执行。

## 源码入口

- `packages/mini-vue/packages/reactivity/src/reactive.ts`
- `packages/mini-vue/packages/reactivity/src/baseHandlers.ts`
- `packages/mini-vue/packages/reactivity/src/effect.ts`
- `packages/mini-vue/packages/reactivity/src/dep.ts`
- `packages/mini-vue/packages/reactivity/src/ref.ts`
- `packages/mini-vue/packages/reactivity/src/computed.ts`
- `packages/mini-vue/packages/runtime-core/src/apiWatch.ts`

## 当前 API 覆盖

| API | 当前状态 | 说明 |
| --- | --- | --- |
| `reactive` | 已实现基础版 | 只支持可变对象代理，按访问递归包装对象值 |
| `effect` | 已实现基础版 | 创建 `ReactiveEffect`，但不返回 runner，`stop()` 为空 |
| `ref` | 已实现基础版 | `.value` 收集/触发依赖，对对象值转 reactive |
| `computed` | 已实现 getter 版 | `_dirty` 缓存，依赖变化时标脏 |
| `watch` | 窄子集 | 主要支持 reactive source、`deep`、`immediate` |

## 依赖图结构

当前实现使用最经典的教学模型：

```text
targetMap: WeakMap<object, Map<key, Dep>>
Dep: Set<ReactiveEffect>
```

展开后是：

```text
响应式原对象 target
  -> 属性 key
    -> 依赖集合 dep
      -> effect A
      -> effect B
```

## 收集和触发

读取属性：

```text
proxy.get
  -> Reflect.get
  -> track(target, key)
  -> dep.add(activeEffect)
```

写入属性：

```text
proxy.set
  -> Reflect.set
  -> trigger(target, key)
  -> triggerEffects(dep)
  -> effect.scheduler() 或 effect.run()
```

`activeEffect` 是一个全局变量。`ReactiveEffect.run()` 会先把当前 effect 写入 `activeEffect`，再执行用户函数。用户函数执行期间读取到的响应式属性，会把这个 effect 收进对应 dep。

## 和组件更新的连接点

组件首次挂载时，`renderer.ts` 会创建组件渲染 effect：

```text
new ReactiveEffect(componentUpdateFn, () => queuePreFlushCb(update))
```

因此组件 render 读取响应式数据时，会把组件 update effect 收集进去。后续数据变化时，`trigger` 不直接更新 DOM，而是通过 scheduler 把组件更新放进微任务队列。

## 重要简化

- 没有 effect 栈，嵌套 effect 会互相覆盖 `activeEffect`。
- 没有依赖 cleanup，同一个 effect 不能从旧 dep 中清理出去。
- `ReactiveEffect.stop()` 是空实现，`watch` 返回的停止函数不会真正停止监听。
- `trackEffects(dep)` 直接 `dep.add(activeEffect)`，没有更细的 shouldTrack、track marker 优化。
- `trigger` 只按精确 `target/key` 触发，没有数组 length、迭代 key、Map/Set 操作的特殊分支。

# 运行时总览

运行时负责把 render 函数返回的 VNode 渲染到宿主环境。当前宿主环境是浏览器 DOM，但 `runtime-core` 本身不直接操作 DOM。

## 源码入口

- `packages/mini-vue/packages/runtime-core/src/vnode.ts`
- `packages/mini-vue/packages/runtime-core/src/renderer.ts`
- `packages/mini-vue/packages/runtime-core/src/component.ts`
- `packages/mini-vue/packages/runtime-core/src/componentRenderUtils.ts`
- `packages/mini-vue/packages/runtime-core/src/scheduler.ts`
- `packages/mini-vue/packages/runtime-core/src/apiCreateApp.ts`
- `packages/mini-vue/packages/runtime-core/src/apiLifecycle.ts`
- `packages/mini-vue/packages/runtime-dom/src/index.ts`
- `packages/mini-vue/packages/runtime-dom/src/nodeOps.ts`
- `packages/mini-vue/packages/runtime-dom/src/patchProp.ts`

## 运行时主流程

```text
createApp(App).mount('#app')
  -> runtime-dom normalizeContainer
  -> runtime-core createVNode(rootComponent)
  -> render(vnode, container)
  -> patch(null, vnode, container)
  -> processComponent
  -> mountComponent
  -> setupComponent
  -> setupRenderEffect
  -> renderComponentRoot
  -> patch(null, subTree, container)
  -> processElement
  -> mountElement
  -> hostCreateElement / hostPatchProp / hostInsert
```

组件更新流程：

```text
响应式数据变化
  -> trigger
  -> 组件 effect.scheduler
  -> queuePreFlushCb(update)
  -> Promise.resolve().then(flushJobs)
  -> update()
  -> renderComponentRoot
  -> patch(prevTree, nextTree)
```

## VNode

`createVNode(type, props, children)` 会生成：

- `type`
- `props`
- `children`
- `shapeFlag`
- `key`
- `__v_isVNode`

`shapeFlag` 用位运算描述节点类型和 children 类型：

- 字符串 `type` 是元素。
- 对象 `type` 是状态组件。
- 数组 children 是 `ARRAY_CHILDREN`。
- 非数组对象以外的 children 会转成字符串，是 `TEXT_CHILDREN`。

## 渲染器

`createRenderer(options)` 接收一组 host 操作：

- `patchProp`
- `setElementText`
- `insert`
- `createElement`
- `remove`
- `createText`
- `setText`
- `createComment`

`runtime-core` 只调用这些抽象操作。浏览器 DOM 的实现由 `runtime-dom` 提供。

## patch 分发

`patch(oldVNode, newVNode, container, anchor)` 会按类型分发：

- `Text` -> `processText`
- `Comment` -> `processCommentNode`
- `Fragment` -> `processFragment`
- `ShapeFlags.ELEMENT` -> `processElement`
- `ShapeFlags.COMPONENT` -> `processComponent`

如果新旧 VNode 的 `type/key` 不同，会先卸载旧节点，再走新节点挂载。

## 组件系统

当前组件实例包含：

- `uid`
- `vnode`
- `type`
- `subTree`
- `effect`
- `update`
- `render`
- `isMounted`
- 生命周期字段 `bc/c/bm/m`

`setupComponent(instance)` 主要处理：

1. 执行 `setup()`。
2. 如果 setup 返回函数，把它作为 `instance.render`。
3. 如果组件没有 render 但有 template，尝试调用注册进来的编译器。
4. 处理 Options API 的 `data` 和少量生命周期。

## scheduler

当前 scheduler 只有 pre flush 队列：

```text
queuePreFlushCb(cb)
  -> pendingPreFlushCbs.push(cb)
  -> Promise.resolve().then(flushJobs)
  -> flushPreFlushCbs()
  -> [...new Set(pendingPreFlushCbs)] 去重后执行
```

这足够支撑组件连续多次状态变化时合并更新，但不是完整 Vue 的 scheduler。

## DOM 适配层

`runtime-dom` 做两件事：

1. 用 `nodeOps` 实现 DOM 节点操作。
2. 用 `patchProp` 处理属性更新。

`patchProp` 的分发顺序：

```text
class
style
event(onXxx)
DOM property
attribute
```

事件模块会把 invoker 缓存在元素的 `_vei` 上。更新事件时只替换 `invoker.value`，避免频繁 remove/add listener。

## 当前边界

- `processComponent` 没有完整的新旧组件更新路径。
- `setup()` 不接收 props/context。
- 没有 props 初始化、attrs、slots、emit、expose、provide/inject。
- 生命周期只有 `beforeCreate`、`created`、`beforeMount`、`mounted` 的部分能力。
- `patchChildren` 的文本/数组切换有 TODO。
- `unmount` 只是 `hostRemove(vnode.el)`，没有递归卸载、组件 effect stop、生命周期清理。
- DOM style patch 只处理对象样式的主要路径，不完整处理字符串样式和自动前缀等。

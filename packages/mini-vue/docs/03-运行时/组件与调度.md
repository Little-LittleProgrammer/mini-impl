# 组件与调度

组件系统负责把组件选项转换成实例，并用响应式 effect 驱动组件更新。

## 组件挂载链路

```text
processComponent(null, vnode, container, anchor)
  -> mountComponent
  -> createComponentInstance
  -> setupComponent
  -> setupRenderEffect
```

当前 `processComponent` 只在 `oldVNode == null` 时挂载组件。组件作为 VNode 被新旧 patch 时，没有完整的组件更新派发逻辑。

## 组件实例

`createComponentInstance(vnode)` 创建的实例包含：

```text
uid
vnode
type
subTree
effect
update
render
isMounted
bc/c/bm/m
```

这是一份非常轻的组件实例模型。完整 Vue 的组件实例还会包含 props、attrs、slots、emit、setupState、ctx、appContext、provides、生命周期数组等。

## setup 处理

当前 `setupStatefulComponent(instance)` 的逻辑：

```text
读取 Component.setup
  -> 如果存在 setup，执行 setup()
  -> 如果 setup 返回函数，作为 instance.render
  -> finishComponentSetup
```

注意：当前 `setup()` 没有传入 `props` 和 `context`。

## template 到 render

`finishComponentSetup(instance)` 中，如果组件没有 render，但有 template，会尝试调用已注册的编译器：

```text
if (compile && !Component.render && Component.template) {
  Component.render = compile(Component.template)
}
```

编译器注册来自 `vue-compat`：

```text
compile(template)
  -> compiler-dom baseCompile
  -> new Function(code)()
  -> render
  -> registerRuntimeCompiler
```

## Options API 的当前处理

`applyOptions(instance)` 支持很小一部分 Options API：

- `data`
- `beforeCreate`
- `created`
- `beforeMount`
- `mounted`

`data()` 返回对象时会被 `reactive(data)` 包装，并挂到 `instance.data`。render 执行时的 `this` 也绑定到 `data`。

## 渲染 effect

`setupRenderEffect` 会创建：

```text
new ReactiveEffect(componentUpdateFn, () => queuePreFlushCb(update))
```

`componentUpdateFn` 分两段：

### 首次挂载

```text
beforeMount
  -> renderComponentRoot(instance)
  -> patch(null, subTree, container, anchor)
  -> mounted
  -> initialVNode.el = subTree.el
  -> instance.isMounted = true
```

### 后续更新

```text
renderComponentRoot(instance)
  -> nextTree
  -> prevTree = instance.subTree
  -> instance.subTree = nextTree
  -> patch(prevTree, nextTree, container, anchor)
  -> next.el = nextTree.el
```

这说明组件内部响应式数据变化可以触发组件更新。但父组件传入 props 后导致子组件更新的完整链路还没有实现。

## scheduler

`scheduler.ts` 的核心是微任务队列：

```text
queuePreFlushCb(update)
  -> pendingPreFlushCbs.push(update)
  -> queueFlush()
  -> Promise.resolve().then(flushJobs)
  -> flushPreFlushCbs()
```

执行前会用 `new Set(pendingPreFlushCbs)` 去重。所以同一个 tick 内同一个 update 多次入队，最终只执行一次。

## 生命周期边界

当前生命周期实现有两个来源：

- Options API：`beforeCreate`、`created` 会在 `applyOptions` 里同步调用。
- 注册式 hook：`beforeMount`、`mounted` 通过 `onBeforeMount/onMounted` 写到实例字段上，再由 renderer 调用。

缺少：

- `beforeUpdate`
- `updated`
- `beforeUnmount`
- `unmounted`
- `errorCaptured`
- `activated/deactivated`
- 多个 hook 数组管理
- setup 中基于当前实例的 hook 注入机制

## 当前组件模型的边界

- 没有 props 标准化和响应式 props。
- 没有 attrs fallthrough。
- 没有 slots。
- 没有 emit。
- 没有 expose。
- 没有 provide/inject。
- 没有组件更新 shouldUpdate 判断。
- 没有组件卸载清理。
- 没有错误边界和异步组件。

这份实现足够说明“组件 render 如何被响应式驱动”，但还不是完整组件系统。

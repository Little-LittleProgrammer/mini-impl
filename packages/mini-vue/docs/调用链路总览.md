# 调用链路总览

这一篇把 mini-vue 的核心执行路径串起来。它适合在读完 [总览](./总览.md) 后阅读。

## 1. createApp 挂载链路

```text
用户调用 createApp(App)
  -> runtime-dom/createApp
  -> ensureRenderer()
  -> createRenderer(rendererOptions)
  -> runtime-core/createAppAPI(render)
  -> 返回 app
```

调用 `mount`：

```text
app.mount('#app')
  -> normalizeContainer('#app')
  -> createVNode(rootComponent, rootProps)
  -> render(vnode, container)
  -> patch(null, vnode, container)
```

如果根节点是组件：

```text
patch
  -> processComponent
  -> mountComponent
  -> createComponentInstance
  -> setupComponent
  -> setupRenderEffect
```

## 2. 组件首次渲染链路

```text
setupRenderEffect
  -> new ReactiveEffect(componentUpdateFn, scheduler)
  -> update()
  -> effect.run()
  -> componentUpdateFn()
```

首次执行 `componentUpdateFn`：

```text
beforeMount
  -> renderComponentRoot(instance)
  -> instance.render.call(data, data)
  -> 得到 subTree
  -> patch(null, subTree, container)
  -> mounted
  -> initialVNode.el = subTree.el
  -> instance.isMounted = true
```

如果 subTree 是普通元素：

```text
patch
  -> processElement
  -> mountElement
  -> hostCreateElement
  -> mountChildren 或 hostSetElementText
  -> hostPatchProp
  -> hostInsert
```

## 3. 响应式更新链路

组件 render 执行期间读取响应式数据：

```text
reactive.get / ref.value
  -> track / trackRefValue
  -> dep.add(组件 ReactiveEffect)
```

后续写入数据：

```text
reactive.set / ref.value =
  -> trigger / triggerRefValue
  -> triggerEffects(dep)
  -> effect.scheduler()
  -> queuePreFlushCb(update)
```

微任务刷新：

```text
Promise.resolve().then(flushJobs)
  -> flushPreFlushCbs()
  -> update()
  -> effect.run()
  -> componentUpdateFn()
```

组件更新阶段：

```text
renderComponentRoot(instance)
  -> nextTree
  -> prevTree = instance.subTree
  -> patch(prevTree, nextTree, container)
  -> next.el = nextTree.el
```

## 4. 模板编译链路

组件没有 render 但有 template 时：

```text
finishComponentSetup
  -> compile(template)
  -> render
  -> instance.render = render
```

编译函数来自 `vue-compat` 注册：

```text
compiler-dom.compile(template)
  -> baseCompile(template)
  -> baseParse(template.trim())
  -> transform(ast)
  -> generate(ast)
  -> { code }
  -> new Function(code)()
  -> render
```

## 5. keyed children diff 链路

元素更新时：

```text
patchElement
  -> patchChildren
  -> patchProps
```

当新旧 children 都是数组：

```text
patchKeyedChildren
  -> 前向同步
  -> 后向同步
  -> 新增挂载
  -> 多余卸载
  -> 乱序区 key map
  -> patch 可复用节点
  -> LIS 减少移动
  -> move / mount 新节点
```

## 6. 四个关键接缝

| 接缝 | 位置 | 作用 |
| --- | --- | --- |
| 响应式 -> 运行时 | `setupRenderEffect` | 组件 render 被 `ReactiveEffect` 包裹 |
| 运行时 -> DOM | `createRenderer(rendererOptions)` | `runtime-dom` 注入 host 操作 |
| 编译器 -> 运行时 | `registerRuntimeCompiler` | template 运行时编译成 render |
| VNode -> DOM | `patch` | 按 VNode 类型分发挂载/更新 |

## 7. 当前链路中断点

- `effect.stop()` 没有实现，卸载和 watch 停止都无法清理依赖。
- `patchChildren` 有多个 TODO，children 类型切换不完整。
- `processComponent` 没有完整组件更新入口。
- 编译器对 props、事件、动态绑定、`v-for`、slot 等没有完整代码生成。

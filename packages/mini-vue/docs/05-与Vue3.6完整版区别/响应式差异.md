# 响应式差异

mini-vue 的响应式实现保留了最容易理解的模型：`WeakMap -> Map -> Set`。完整 Vue 的响应式系统要处理更多 API、更多数据结构和更严格的依赖生命周期。

## mini-vue 当前模型

```text
targetMap: WeakMap<object, Map<key, Set<ReactiveEffect>>>
activeEffect: ReactiveEffect | undefined
```

核心过程：

```text
get -> track -> dep.add(activeEffect)
set -> trigger -> effect.scheduler() 或 effect.run()
```

这个模型适合教学，但不是完整实现。

## effect 生命周期差异

mini-vue：

- `ReactiveEffect.run()` 只设置 `activeEffect` 并执行 `fn`。
- `stop()` 是空实现。
- 没有 effect 栈。
- 没有 cleanup。
- 没有反向记录 effect 依赖了哪些 dep。

完整 Vue：

- effect 有 active 状态。
- effect 可以停止。
- 停止时要从所有 dep 中移除。
- 嵌套 effect 要正确恢复父 effect。
- 有递归触发保护和调试钩子。

## reactive API 差异

mini-vue 只有基础 `reactive`。

完整 Vue 还包括：

- `readonly`
- `shallowReactive`
- `shallowReadonly`
- `isReadonly`
- `isProxy`
- `toRaw`
- `markRaw`
- 集合类型 instrumentations
- 数组方法特殊处理

mini-vue 的 `set` 不区分新增、修改、删除，也不会因为值未变化而跳过 trigger。

## ref API 差异

mini-vue 有：

- `ref`
- `isRef`

完整 Vue 还包括：

- `shallowRef`
- `triggerRef`
- `customRef`
- `unref`
- `toRef`
- `toRefs`
- `proxyRefs`

## computed 差异

mini-vue：

- 只支持 getter 函数。
- 用 `_dirty` 标记缓存。
- 依赖变化时标脏，下次读取再计算。

完整 Vue：

- 支持 writable computed。
- 有更完整的调试和缓存行为。
- 与复杂调度、依赖清理协同。

## watch 差异

mini-vue 的 `watch` 主要支持 reactive source、`deep`、`immediate`。

完整 Vue 支持：

- ref source。
- getter source。
- source 数组。
- `watchEffect` / `watchPostEffect` / `watchSyncEffect`。
- `flush` 选项。
- cleanup / invalidation。
- stop 真实生效。

mini-vue 返回的 stop 函数调用了 `effect.stop()`，但当前 `stop()` 为空，因此无法真正停止监听。

## Vue 3.6 beta 方向

npm registry 显示 `vue@beta` 当前是 `3.6.0-beta.15`，对应 `@vue/reactivity@3.6.0-beta.15` 已单独发布。公开 beta 包说明 3.6 响应式仍是独立包体系的一部分，但不能仅凭 mini-vue 的教学模型推断 3.6 内部实现。

可以确定的是：mini-vue 没有实现 3.6 beta 级别的响应式优化、内存优化或 Vapor 路线协同。

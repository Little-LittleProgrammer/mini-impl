# 运行时差异

mini-vue 的运行时保留了 VNode、renderer、组件 effect、DOM host ops 的主干。完整 Vue 的运行时还要处理生产级组件模型、平台边界、SSR/hydration 和大量内建能力。

## 组件模型差异

mini-vue 组件实例只有少量字段：

- `uid`
- `vnode`
- `type`
- `subTree`
- `effect`
- `update`
- `render`
- `isMounted`
- 少量生命周期字段

完整 Vue 组件实例还需要处理：

- props / attrs
- slots
- emit
- setup state
- public instance proxy
- app context
- provides
- expose
- refs
- suspense
- async setup
- devtools / warning context

mini-vue 当前 `setup()` 不接收 props/context，也没有 slots/emit。

## 更新机制差异

mini-vue 能做到：

```text
响应式数据变化
  -> 组件 effect scheduler
  -> 微任务队列
  -> 重新 render
  -> patch subTree
```

完整 Vue 还要处理：

- 父子组件更新顺序。
- 组件是否需要更新的判断。
- props 更新。
- slots 更新。
- job id 排序。
- pre/post flush callbacks。
- 递归更新限制。
- 错误处理。

## diff 和卸载差异

mini-vue 已有 keyed children diff 主干：

- 头部同步。
- 尾部同步。
- 新增挂载。
- 多余卸载。
- 乱序 key map。
- 最长递增子序列减少移动。

但它仍缺：

- children 类型切换的完整分支。
- 递归卸载。
- 组件卸载。
- Fragment 完整卸载。
- effect stop 和生命周期清理。
- ref 清理。

完整 Vue 的卸载不是简单 `remove(el)`，而是一套组件树和副作用树清理流程。

## DOM 运行时差异

mini-vue 的 DOM 适配层支持基础：

- class
- style
- event
- DOM prop
- attribute
- text/comment 创建
- selector mount

完整 Vue 还要覆盖：

- SVG / MathML namespace。
- 表单元素的细节。
- 事件 option、时间戳、边界处理。
- CSS 变量、自动前缀、字符串样式。
- hydration DOM 操作。
- transition 参与的插入和移除。

## 内建组件差异

mini-vue 没有：

- Teleport
- Transition
- TransitionGroup
- KeepAlive
- Suspense
- async component

这些能力不是“多几个 API”，而是会深度影响 renderer、scheduler、组件生命周期和卸载逻辑。

## Vue 3.6 beta 的运行时路线

npm registry 中 `vue@3.6.0-beta.15` 的依赖包含：

- `@vue/runtime-dom`
- `@vue/runtime-vapor`
- `@vue/server-renderer`

构建格式中也包含：

- `esm-browser-vapor`

这说明 3.6 beta 包体系里已经存在 Vapor 相关运行时。mini-vue 完全没有这条路线，它只展示经典 VNode renderer。

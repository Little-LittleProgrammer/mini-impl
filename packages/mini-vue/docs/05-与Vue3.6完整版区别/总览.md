# 与 Vue 3.6/完整版的区别

这部分不是逐项 API 清单，而是帮助你判断：当前 mini-vue 到底解释了 Vue 的哪一层，哪些内容不能拿它类比完整 Vue。

## 对比基线

截至 2026-06-13，通过 npm registry 查询：

- `vue@latest` 是 `3.5.38`。
- `vue@beta` 是 `3.6.0-beta.15`。
- `vue@3.6.0-beta.15` 的依赖中包含 `@vue/runtime-vapor`，构建格式包含 `esm-browser-vapor`。

所以本文中的“Vue 3.6”指公开 beta 包体现出来的方向；“完整版”指完整 Vue 3 稳定能力和官方包体系，不把 3.6 beta 细节写成稳定版承诺。

## 一句话定位

mini-vue 是“Vue 3 经典 VDOM 架构的教学骨架”。完整 Vue 是“生产级响应式 + 完整组件模型 + 编译优化闭环 + 多平台/SSR/SFC 生态”。Vue 3.6 beta 还额外出现了 Vapor 相关运行时路线。

## 总体差异

| 维度 | mini-vue | 完整 Vue / Vue 3.6 beta |
| --- | --- | --- |
| 响应式 | WeakMap/Map/Set 教学模型 | 生产级依赖管理、cleanup、调度、集合类型、调试能力 |
| 运行时 | VNode + patch + 基础组件 effect | 完整组件实例、props/slots/emit、内建组件、SSR/hydration |
| 编译器 | parse/transform/codegen 骨架 | SFC、模板完整语法、patch flags、block tree、优化闭环 |
| DOM | 基础 nodeOps/patchProp | 完整 DOM 边界、事件、表单、SVG、hydration |
| 调度 | 单个 pre flush 微任务队列 | 多队列、优先级、递归保护、组件更新排序 |
| 3.6 方向 | 没有 Vapor | beta 包包含 `@vue/runtime-vapor` 和 vapor 构建 |

## 当前 mini-vue 学得到什么

- Vue 为什么把响应式、运行时、编译器拆开。
- `reactive/ref` 如何通过依赖图驱动副作用。
- 组件 render 为什么可以被响应式数据自动重新执行。
- VNode diff 的基本分发和 keyed children diff 主干。
- 模板如何经过 AST 转换后生成 render code。
- 运行时和编译器如何通过 `registerRuntimeCompiler` 接起来。

## 当前 mini-vue 学不到什么

- 完整 Vue 的响应式边界和性能优化。
- 完整组件实例模型。
- 生产级调度器。
- 完整模板语法编译。
- SFC 编译链。
- SSR 和 hydration。
- 内建组件实现。
- Vue 3.6 beta 的 Vapor Mode 架构。

# 编译时差异

mini-vue 的编译器是教学流水线：解析模板、转换 AST、生成 render 字符串。完整 Vue 的编译器是生产工具链的一部分，要和运行时优化、SFC、SSR、类型和生态协同。

## 模板语法差异

mini-vue 当前支持：

- 元素。
- 文本。
- 插值。
- 基础属性节点。
- 基础 `v-if`。
- 相邻文本合并。

完整 Vue 支持：

- `v-if / v-else-if / v-else`
- `v-for`
- `v-bind`
- `v-on`
- `v-model`
- `v-show`
- slot / scoped slot
- dynamic component
- directive runtime
- modifier
- component resolution
- fragment

当前 mini-vue 对 `v-on`、`v-bind` 等指令即使能解析成指令节点，也没有生成完整运行时代码。

## 优化体系差异

mini-vue 没有完整优化闭环。

完整 Vue 的编译器会生成运行时需要的优化信息，例如：

- patch flags
- dynamic props
- block tree
- hoists
- cache expressions
- 静态节点提升
- 事件缓存

mini-vue 里虽然有 `hoistStatic.ts` 文件名和一些 AST 节点类型，但没有形成完整优化产物，也没有和 runtime patch 形成闭环。

## SFC 差异

mini-vue 没有 SFC 编译链。

完整 Vue 的 SFC 编译涉及：

- `<template>`
- `<script>`
- `<script setup>`
- `<style scoped>`
- CSS vars
- source map
- HMR 边界
- TypeScript 辅助分析

mini-vue 的运行时模板编译只是：

```text
template string
  -> compile(template)
  -> code string
  -> new Function(code)()
```

## SSR/hydration 差异

mini-vue 没有 SSR 编译器，也没有 hydration runtime。

完整 Vue 需要：

- 服务端字符串渲染。
- hydration mismatch 处理。
- SSR 特定 codegen。
- streaming。
- Suspense 与 SSR 协同。

## Vue 3.6 beta 的编译方向

npm registry 显示 `vue@3.6.0-beta.15` 同时依赖：

- `@vue/compiler-dom`
- `@vue/compiler-sfc`
- `@vue/runtime-vapor`

并包含 `esm-browser-vapor` 构建格式。这意味着 3.6 beta 的包体系不只是传统 VDOM 编译路径，还包含 Vapor 相关产物。

mini-vue 的编译器没有 Vapor 编译目标，也没有传统 VDOM 的完整优化目标。

## 正确学习预期

通过 mini-vue 编译器可以学到：

- AST 是怎么来的。
- transform 为什么需要进入/退出两个阶段。
- helper 如何被收集。
- render 函数字符串如何拼出来。

不要用它推断完整 Vue 编译器的能力覆盖、错误处理、优化策略和 SFC 行为。

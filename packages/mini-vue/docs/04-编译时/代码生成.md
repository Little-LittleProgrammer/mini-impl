# 代码生成

代码生成阶段把转换后的 AST 输出为 render 函数字符串。入口是 `generate(ast)`。

## 生成上下文

`createCodegenContext(ast)` 维护：

- `code`
- `runtimeGlobalName: 'Vue'`
- `indentLevel`
- `helper(key)`
- `push(code)`
- `newline()`
- `indent()`
- `deindent()`

生成器本质上是逐步拼接字符串。

## 输出结构

当前输出大致是：

```js
const _Vue = Vue

return function render(_ctx, _cache) {
  with (_ctx) {
    const { createElementVNode: _createElementVNode } = _Vue

    return _createElementVNode("div", [], ["hello"])
  }
}
```

`vue-compat` 会执行：

```ts
new Function(code)()
```

所以 `code` 的开头必须能返回一个 render 函数。

## helper 导入

转换阶段记录的 `ast.helpers` 会在 render 函数内部生成解构：

```text
const { helperName: _helperName } = _Vue
```

例如插值会记录 `TO_DISPLAY_STRING`，codegen 生成：

```text
_toDisplayString(msg)
```

## genNode

`genNode(node, context)` 根据节点类型分发：

- `ELEMENT`
- `IF`
- `VNODE_CALL`
- `TEXT`
- `SIMPLE_EXPRESSION`
- `INTERPOLATION`
- `COMPOUND_EXPRESSION`
- `JS_CALL_EXPRESSION`
- `JS_CONDITIONAL_EXPRESSION`

未覆盖的节点类型不会生成有效代码。

## VNode call

`genVNodeCall` 会生成：

```text
_createElementVNode(tag, props, children, patchFlag, dynamicProps)
```

当前 `transformElement` 传入的 props 是 `[]`，children 是 AST children 数组。因此这不是完整 Vue 的 VNode 代码生成格式，只是项目当前实现的简化格式。

## 插值

模板：

```html
<div>{{ msg }}</div>
```

插值节点会生成：

```text
_toDisplayString(msg)
```

因为 render 函数用了 `with (_ctx)`，这里的 `msg` 会从 `_ctx` 上解析。

## v-if

`v-if` 会生成 JS 条件表达式：

```text
ok
  ? _createElementVNode(...)
  : _createCommentVNode("v-if", true)
```

当前没有完整处理 `else-if` / `else` 链。

## 当前代码生成边界

- 依赖 `with (_ctx)`，没有 prefixIdentifiers 模式。
- 没有完整对象表达式输出。
- 没有事件表达式、动态 props、指令 runtime 的生成。
- 没有 block tree、patch flags、hoists。
- 没有 source map。
- 没有 SSR codegen。
- 多根模板通常无法得到完整 `root.codegenNode`。

所以这份 codegen 适合理解“AST 如何变成 render 字符串”，不是完整 Vue 编译产物。

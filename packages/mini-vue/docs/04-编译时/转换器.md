# 转换器

转换器把解析阶段得到的模板 AST 改写成更适合代码生成的结构，并收集运行时 helper。

## transform 上下文

`createTransformContext(root, options)` 创建上下文，核心字段包括：

- `root`
- `parent`
- `childIndex`
- `currentNode`
- `helpers`
- `nodeTransforms`
- `helper(name)`
- `replaceNode(node)`

`helpers` 用来记录 render 函数需要从 `Vue` 上解构哪些方法。

## 遍历模型

`traverseNode(node, context)` 采用“进入 + 退出”模型：

```text
进入节点
  -> 依次执行 nodeTransforms
  -> 收集 transform 返回的退出函数
  -> 如果节点被 replace，更新当前 node
遍历子节点
退出节点
  -> 倒序执行退出函数
```

退出函数倒序执行，是为了让子节点先完成转换，父节点再基于子节点结果生成自己的 `codegenNode`。

## transformElement

`transformElement` 在退出阶段处理元素节点：

```text
ELEMENT
  -> vnodeTag = `"${tag}"`
  -> vnodeProps = []
  -> vnodeChildren = node.children
  -> node.codegenNode = createVNodeCall(...)
```

当前 props 生成是空数组，不是完整 Vue 的 props 表达式。

## transformText

`transformText` 用于合并相邻文本类节点：

```html
<div>hello {{ msg }}</div>
```

会把相邻的文本和插值变成复合表达式：

```text
TEXT("hello ")
" + "
INTERPOLATION(msg)
```

这样 codegen 可以生成字符串拼接表达式。

## transformIf

`transformIf` 通过 `createStructuralDirectiveTransform` 匹配：

```text
/^(if|else|else-if)$/
```

当前真正实现的是 `v-if` 根分支：

```text
带 v-if 的元素
  -> 创建 IF_BRANCH
  -> 创建 IF 节点
  -> context.replaceNode(ifNode)
  -> 退出阶段创建 JS_CONDITIONAL_EXPRESSION
```

条件不成立时，会生成注释 VNode：

```text
createCommentVNode("v-if", true)
```

## createRootCodegen

转换结束后，`createRootCodegen(root)` 只处理单根元素：

```text
如果 root.children.length === 1
  且 child 是单个元素根节点
  且 child.codegenNode 存在
  -> root.codegenNode = child.codegenNode
```

这也是当前多根模板能力不足的原因之一。

## 当前转换器边界

- `v-if` 的 `else-if/else` 兄弟分支没有完整实现。
- `v-for` 没有 transform。
- 动态 props、事件、指令参数、修饰符没有生成。
- 组件节点没有解析和转换。
- slot 没有转换。
- 没有 patch flag、block tree、静态提升闭环。
- `transformElement` 的 props 当前是 `[]`，不是完整 props codegen。

转换器目前展示的是 Vue 编译器“插件化遍历和 codegenNode 生成”的骨架。
